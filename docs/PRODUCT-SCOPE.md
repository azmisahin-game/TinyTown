# Product scope

## v0.1 — the first complete experience

### Required

- A native C++ application that configures and builds through CMake.
- A compact stylized 3D town derived from the reference prototype: road, sidewalks, buildings, windows, a few props, sky/lighting, camera, and collision boundaries.
- Window resize and close behave correctly; input state is cleared after focus loss.
- Smooth, frame-rate-independent movement and camera input. Sensible movement bounds and mouse behaviour.
- Deterministic procedural world generation controlled by a seed, with a way to reset/recreate the world.
- At least three visibly distinct agents in the town. Their first behaviours are simple and explainable: patrol between points, travel to a target, or deliver a package.
- Basic navigation that avoids buildings. The world may use a small grid/waypoint graph; do not build a general navigation framework.
- A small inspect panel that shows selected agent, current task/state, target, and whether the task succeeded or failed.
- A clearly visible way to pause/resume or reset the simulation.
- A short controls/help overlay and a polished initial scene.
- Unit tests for core simulation and path/agent state behaviour that can run without graphics.
- A README with real build commands, controls, known limitations, and honest platform support.

### Quality bar

The first version should feel like a tiny product, not a bare cube test. Use a restrained art direction (for example, soft low-poly / miniature diorama), coherent scale, a readable road layout, varied building silhouettes, window details, subtle ambient animation, and clear visual hierarchy. Prefer fewer well-composed objects over a huge empty city.

The application must still be usable if optional audio is muted or unavailable. Avoid forced camera movement, flashing effects, loud surprises, and controls that trap the cursor.

### Explicitly not required for v0.1

- LLMs, agent frameworks, API keys, cloud accounts, or downloaded model weights.
- AI image generation, natural-speech TTS, or realistic AI video generation.
- An in-app scene editor, plugin marketplace, scripting language, multi-user system, or large open world.
- MP4 export. Establish and test the core world first.
- Browser/WebAssembly release before the native core is working.

## v0.2 — a useful creative output

After v0.1 is stable:

- Add a procedural ambient soundscape with master volume/mute controls, generated without audio files.
- Add still-image export or a deterministic frame-capture mode.
- Provide a simple animation capture workflow. A platform-independent image sequence is a valid first deliverable; WAV audio can be generated separately.
- Add MP4 muxing only as an optional FFmpeg integration, after checking distribution/licensing implications and clear failure behaviour.
- Add screenshot/GIF/clip examples generated by the actual build.

## v0.3 — broader reach

- Explore a browser/WebAssembly build from the same simulation and world-generation core.
- Deploy a browser demo with GitHub Pages only once a real, working build exists.
- Add macOS and other targets after documenting toolchain and graphics constraints, not merely by adding a CI matrix entry.

## v1.x — optional intelligence adapters

Only after the base experience works well, explore isolated, optional adapters:

- LLM planner for high-level goals, while deterministic simulation validates and executes actions.
- TTS for agent speech or narration.
- AI image/video model or service integration, if there is a concrete use case and acceptable hardware/licensing requirements.

The base world must continue to run if every adapter is absent or fails. Do not include all these integrations in one milestone.
